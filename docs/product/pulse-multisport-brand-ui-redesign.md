# PULSE 多运动平台品牌与 UI 改版设计方案

> 状态：设计方向提案 1.2（保留 F1 四类 Session 的杆位/冠军与前三预测；强化原创视觉母题、页面构图与交互规范）  
> 日期：2026-07-16  
> 适用项目：`football-predictor`  
> 目标：从足球单项产品升级为足球、篮球、F1 共存的多运动社交预测平台

---

## 1. 执行摘要

当前产品已经具备可复用的核心能力：真实赛事、好友房间、虚拟积分、预测票据、自动封盘、自动结算、账本、排行榜和管理能力。真正限制产品扩展的不是这些业务能力，而是三层“足球绑定”：

1. **品牌绑定**：名称、Logo、PWA 元数据和主文案全部是 football / 足球；
2. **界面绑定**：足球、球场、哨子、Matchday 等视觉符号贯穿全站；
3. **模型绑定**：主客队、胜平负、正确比分等结构无法自然表达 F1 多车手赛事。

本方案建议：

- 工作品牌升级为 **PULSE**；
- 核心品牌色改为 **赛车红 + 碳黑 + 暖白**；
- 保留少量荧光黄绿作为实时状态和关键数据高亮；
- 使用原创的“P + 赛道弧线 + 速度切口”Logo，不直接使用跃马、盾牌或 Ferrari 识别元素；
- 建立贯穿 Logo、导航、赛事状态和页面转场的原创 **PULSE LINE** 视觉母题，避免沦为普通的红黑赛车模板；
- 首页和品牌页采用类似顶级运动员官网的高冲击编辑式设计；
- 登录后的功能区降低视觉噪音，强调信息密度、赛事状态和操作效率；
- 足球、篮球、F1 共用品牌系统，但拥有不同的赛事卡和运动图形语言；
- 先完成品牌原型，再建设通用赛事模型，避免 UI 和后端同时失控。

### 一句话定位

> **PULSE 是朋友之间记录体育判断、虚拟积分和长期战绩的多运动竞技俱乐部。**

### 推荐品牌口号

英文主口号：

> **CALL THE MOMENT.**

中文主口号：

> **每一刻，都有判断。**

辅助文案：

> 足球、篮球、F1。和朋友一起预测，用虚拟积分留下每一次判断。

## 2. 调研范围与观察

### 2.1 Lando Norris 官网

2026-07-16 对 [Lando Norris 官方网站](https://landonorris.com/) 的公开页面与 CSS 观察结果：

- 页面使用非常明确的双主色：荧光黄绿 `#D2FF00` 与近黑 `#101400`；
- 主要字体为定制展示字体 Brier，正文使用 Mona Sans Variable；
- 首页用极大的姓名和 On Track / Off Track 章节制造人物品牌感；
- 当前公开信息架构包括 Home、On Track、Off Track、Partnerships、Calendar、Store；
- 首屏、媒体区、头盔陈列、赛历和合作品牌共同形成“人物世界”，而不是传统资讯站；
- 大标题大量采用 7rem、视口自适应字号、全大写和窄行高；
- 圆角克制，许多区块接近直角或小圆角，整体更像赛车海报和时尚编辑页；
- 页面媒体密度很高，使用图片、视频和裁切来承载情绪，文字只承担方向和动作。

参考：

- [Lando Norris 官网](https://landonorris.com/)
- [官网公开样式表 1](https://cdn.prod.website-files.com/67b5a02dc5d338960b17a7e9/css/lando-offbrand.shared.043b62fef.css)
- [官网公开样式表 2](https://cdn.prod.website-files.com/67b5a02dc5d338960b17a7e9/css/lando-offbrand.shared.4f53262f0.css)

**适合借鉴的部分**：高反差、超大文字、编辑式分区、运动员海报感、数字与媒体的组合、简洁导航、强动效节奏。

**不适合直接复制的部分**：个人明星叙事、专属字体、照片构图、荧光绿比例、具体章节结构和商业合作展示。

### 2.2 Ferrari / 红色跃马的吸引力

用户喜欢“红色跃马”，本质上通常来自四种感受：

1. 极高辨识度的红色；
2. 速度、力量和胜利姿态；
3. 徽章带来的历史与俱乐部感；
4. 红、黑、黄之间的豪华与竞技张力。

本项目应提取的是这些**情绪与设计机制**，而不是复制跃马图形、黄色盾牌、SF 字母或 Ferrari 红的精确组合。

参考：

- [Scuderia Ferrari 官方 F1 页面](https://www.ferrari.com/en-EN/formula1)
- [Formula 1 官方首页](https://www.formula1.com/)

### 2.3 F1 与 NBA 官方赛事页面

[F1 官方首页](https://www.formula1.com/)当前以视频、编辑推荐、赛季入口、车手与比赛内容为核心，强化赛事故事和即时内容；[NBA Games](https://www.nba.com/games)则把日期、比分、赛况和操作入口压缩在高密度赛程结构中。

这说明我们的产品需要同时具备两种界面模式：

- **品牌模式**：首页、营销页、空状态，高冲击、高情绪、强媒体；
- **工具模式**：赛事、预测、房间、账本，高密度、低干扰、操作明确。

不能把首页的海报式设计机械复制到每一张业务表格。

## 3. 当前项目设计审计

### 3.1 可以继承的资产

当前 `apps/web/src/app/globals.css` 已经拥有：

- `--night` 深色场景；
- `--volt` 荧光强调色；
- `.kinetic` 超大运动字体；
- `.marquee` 横向赛事条；
- `.reveal` 滚动显现；
- `.line-art` 流体线条背景；
- 深色 Hero、粗体 CTA、动态 Loading；
- `prefers-reduced-motion` 降级支持。

这意味着视觉重构不是从零开始，应该升级现有系统而不是再叠加第三套 CSS。

### 3.2 必须解除的足球绑定

当前前端约有：

- 42 个文件包含 football / 足球 / SoccerBall / Matchday 等品牌语言；
- 约 130 处足球品牌引用；
- 约 144 处主客队或 HOME / DRAW / AWAY 相关模型引用。

高优先级改造点：

| 当前文件/能力 | 当前问题 | 改版方向 |
|---|---|---|
| `brand-mark.tsx` | 足球作为 Logo | 使用 PULSE 原创中性 Logo |
| `layout.tsx` | Metadata 固定 football | 使用 PULSE 多运动描述 |
| `home-experience.tsx` | FOOTBALL 巨型标题 | 改为 PULSE 品牌首页 |
| `private-shell.tsx` | Matchday Ledger | 改为统一 Sports Club Shell |
| `football.tsx` | 全站装饰图标来源 | 拆为通用运动图标系统 |
| `match-card.tsx` | 只适配双方球队 | 拆为 Football、Basketball、F1 三类卡片 |
| `KickoffLoader` | 只表达开球 | 改为通用 PULSE Loader |

### 3.3 当前视觉风险

- 米白、草绿、荧光绿、珊瑚红同时作为高优先级颜色，品牌焦点不够集中；
- 首页已经比较大胆，业务页仍然偏传统后台，两个世界连接不够顺畅；
- 足球图形使用过多，新运动加入后容易变成图标拼盘；
- 所有按钮都依赖颜色表达，未来品牌红会与错误/删除语义冲突；
- 当前字标只是普通小写 `football`，缺少真正的品牌资产。

## 4. 品牌策略

### 4.0 设计北极星：红色竞技编辑部

PULSE 不做“科技大屏”，也不做“换成红色的博彩网站”。它应当像一本每天实时更新的高端赛车与球赛杂志：**封面大胆、正文克制、数字准确、状态清楚**。

用户进入页面时首先感受到速度和比赛气氛；真正开始预测时，界面立即退后，让赛事、时间、倍率和积分成为主角。

第一版必须守住三个记忆点：

1. **一条线**：PULSE LINE 从品牌图形延伸到赛事时间轴和交互反馈；
2. **一个切口**：所有关键标题和选中状态共享 11° 向前切角；
3. **一个红场**：每个页面最多只有一个大面积红色视觉焦点，其余区域用碳黑和暖白承载。

如果移除 Logo 后页面只剩“红 + 黑 + 大字”，说明设计仍不成立。

### 4.1 推荐名称：PULSE

品牌锁定形式：

```text
PULSE
SPORTS CLUB
```

中文辅助名：

```text
PULSE 赛事脉搏
```

推荐 PULSE 的原因：

- 心跳、实时、节奏、赛场氛围天然相关；
- 不绑定足球、篮球或赛车；
- 可以延伸到网球、电竞等未来品类；
- 红色与 PULSE 的心跳语义高度一致；
- 字母 P 适合做赛道和速度切口；
- 不直接让产品看起来像博彩品牌。

**名称查重（2026-07-17）**：体育 App 领域「Pulse」已较拥挤（PULSE Sport 运动员管理系统、Pulse Click: Live Sports、Sportpulse、Pulselive、Pulse Sports LLC 持有多个商标等），但无一家与「好友房间虚拟积分预测」品类重合。本产品为自部署 PWA、不上应用商店，实际冲突风险低。结论：工作品牌可用，对外统一使用完整组合 **PULSE SPORTS CLUB** 做差异化；未来若上架应用商店或注册商标，需先做正式商标检索。

### 4.2 品牌人格

| 维度 | 目标 |
|---|---|
| 情绪 | 热烈，但不躁动 |
| 速度 | 快，但不轻浮 |
| 专业 | 数据可靠，但不做数据终端 |
| 社交 | 有对抗，但不攻击用户 |
| 高级感 | 来自留白、比例和细节，不来自金色堆叠 |

### 4.3 语言规范

应该使用：

- 预测
- 判断
- 投入积分
- 预计返还
- 赛事
- 自动结算
- 战绩
- 房间排名

避免使用：

- 下注
- 赌博
- 赢钱
- 赔率投注
- 提现
- 充值

产品继续明确：虚拟积分不可充值、提现或兑换。

## 5. Logo 设计方案

### 5.1 推荐方案 A：PULSE SLASH

> **2026-07-17 拍板：方案 A / A1 基准型已选定为主 Logo 方向**（A3 红底碳黑 P 为其 PWA 图标变体，A2 鬃毛切线留档不用）。结构草案已在 `/design-system` 样板页落地，待精修图稿。

主图形由三个部分构成：

1. 向前倾斜的字母 `P`；
2. `P` 内部负空间形成一条高速弯道；
3. 右下角切出两道速度缺口，形成前进方向。

视觉印象：

```text
     ╭──╮
  ╱P │  │  →
 ╱   ╰──╯ //
```

这不是最终图稿，只表达结构：粗壮、倾斜、重心向前、内部有轨迹。

#### 与“跃马感”的关系

不画一匹真正站立的马，而是在 P 的顶部加入一条像鬃毛向后飞扬的切线。观看者可以感受到“冲锋”和“跃起”，但不会直接联想到 Ferrari 盾牌。

### 5.2 备选方案 B：RED CHARGER

使用两条连续曲线形成：

- 上方：冲刺中的头部和鬃毛动势；
- 下方：赛道与心跳曲线；
- 图形整体保持抽象，不出现马腿、马尾和直立跃马姿势。

适合作为赛事海报或会员徽章，不建议作为第一版主 Logo，因为抽象动物图形在小尺寸下更难识别。

### 5.3 不采用的方案

- 黄色盾牌 + 黑色马；
- 直立跃马姿势；
- 红黄黑三色 Ferrari 式徽章；
- `SF` 或类似 Scuderia 字母结构；
- F1 赛车作为品牌图形；
- 足球、篮球、方向盘三图标并排。

### 5.4 Logo 使用规格

| 场景 | 使用形式 |
|---|---|
| 桌面 Header | P 图形 + PULSE 字标 |
| 移动端 Header | 单独 P 图形 |
| PWA 图标 | 红底、碳黑 P |
| 深色背景 | 红色或暖白 Logo |
| 红色背景 | 碳黑 Logo |
| 极小尺寸 | 只保留 P，不显示 SPORTS CLUB |

Logo 周围安全空间至少等于 P 图形内部圆孔宽度。

### 5.5 字标与动态识别

`PULSE` 字标不直接使用现成字体输出。以 Anybody Variable Black 为骨架，手工调整 `P` 的内孔、`S` 的上下重心，并在 `E` 末端加入与 Logo 相同的 11° 切口。

动态 Logo 只允许一次完整动作：P 的内部赛道先出现，速度切口随后打开，最后字标进入。总时长不超过 520ms；Loading 场景只使用 P 图形的线段推进，不让整个 Logo旋转。

品牌最小识别组合为：**P 图形 + 11° 切口 + PULSE LINE**。任何单项运动图标都不能进入主 Logo。

## 6. 色彩系统

### 6.1 核心颜色

```css
:root {
  --pulse-carbon: oklch(13% 0.008 155);
  --pulse-carbon-2: oklch(18% 0.010 155);
  --pulse-red: oklch(65% 0.235 32);
  --pulse-red-deep: oklch(43% 0.175 30);
  --pulse-ivory: oklch(95.5% 0.018 91);
  --pulse-paper: oklch(98% 0.010 91);
  --pulse-lime: oklch(92% 0.235 119);
  --pulse-muted: oklch(64% 0.012 155);
  --pulse-line-dark: rgba(255,255,255,.14);
  --pulse-line-light: rgba(8,9,9,.16);
}
```

颜色不是 Ferrari 官方色值的复刻。红色需要更偏数字产品和屏幕表现。

工程实现以 OKLCH Token 为主，同时生成十六进制 fallback。暖白不是纯白，碳黑也不是纯黑，减少长时间阅读的刺眼感。

### 6.2 色彩比例

```text
碳黑       45%
暖白       30%
赛车红     20%
荧光黄绿    3%
运动辅助色  2%
```

红色是品牌动作色，不是整页背景色。连续的大红色页面会快速疲劳，并削弱比赛结果和错误状态的区分。

荧光黄绿严格限定在 `LIVE`、数据刚更新和当前最快等实时状态，不用于普通 CTA。这样当它出现时才真正有意义。

### 6.3 可访问性组合

已按 WCAG 相对亮度公式计算：

| 前景 / 背景 | 对比度 | 使用建议 |
|---|---:|---|
| 碳黑 `#080909` / 红 `#FF3B20` | 5.60:1 | 可用于普通文字和按钮 |
| 白 / 深红 `#B8170D` | 6.63:1 | 可用于普通文字 |
| 碳黑 / 荧光绿 `#D2FF00` | 17.13:1 | 实时状态和强 CTA |
| 碳黑 / 暖白 `#F4F1E8` | 17.65:1 | 主内容区 |
| 白 / 红 `#FF3B20` | 3.56:1 | 仅限大号粗体，不用于小文字 |

参考：[WCAG 2.2 Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

### 6.4 品牌红与错误红的处理

品牌已经使用红色后，危险操作不能只依靠红色表达。建议：

- 品牌主按钮：红底 + 碳黑文字；
- 删除/封禁：深红描边 + 危险图标 + 明确动词；
- 错误消息：淡红背景 + 深红文字 + 图标；
- 比赛 LIVE：荧光绿或白色脉冲点，不再默认红色；
- 已结束：中性灰；
- 成功：青绿色，不与品牌红冲突。

## 7. 字体系统

### 7.1 字体建议

不复制 Lando Norris 的 Brier 定制字体。

推荐组合：

```text
英文品牌展示：Anybody Variable Black（宽度轴用于运动切换，不做循环动画）
英文数据标题：Barlow Condensed ExtraBold / Black
中文大标题：Source Han Sans SC Heavy
正文：Source Han Sans SC / system-ui
数字与遥测：IBM Plex Mono SemiBold
```

全部字体应确认 OFL/开源许可并以本地 WOFF2 随应用发布，避免中国网络环境加载外部 Google Fonts。`IBM Plex Mono` 只用于比分、时间、圈速、倍率和积分，不用于导航、按钮或正文，避免把产品做成通用“开发者终端风”。

### 7.2 字号比例

```css
--type-hero: clamp(4.5rem, 16vw, 13rem);
--type-display: clamp(3rem, 9vw, 7rem);
--type-section: clamp(2.25rem, 6vw, 4.5rem);
--type-card-title: clamp(1.5rem, 3vw, 2.25rem);
--type-body: 1rem;
--type-caption: .75rem;
```

### 7.3 数字设计

比分、积分、赔率、圈速和排名统一使用：

- 等宽数字；
- `font-variant-numeric: tabular-nums`；
- 数字字号大于标签至少 1.8 倍；
- 小数位对齐；
- 变化值使用箭头和正负号，不只依赖颜色。

## 8. 布局与形状语言

### 8.1 12 列编辑网格

桌面使用 12 列网格，最大内容宽度 1440px：

- 首页 Hero 可突破容器，形成海报感；
- 功能页面最大宽度保持 1200–1280px；
- 赛事卡至少占 4 列；
- F1 起跑阵容和排行榜允许整行 12 列；
- 手机统一单列，避免横向压缩数据。

### 8.2 形状原则

- 品牌区块：0–8px 小圆角，硬朗；
- 功能卡片：12px 圆角，保证亲和力；
- 标签与筛选：胶囊形；
- 大面积容器不使用 24px 以上圆角；
- 使用 8–12 度斜切边表达速度；
- 斜切只用于标题条、标签和媒体裁切，不用于表单输入框。

### 8.3 线条系统

统一使用“运动轨迹线”，不为每项运动堆叠写实图标：

- 足球：中圈、禁区弧、传球虚线；
- 篮球：三分弧、罚球区、24 秒环；
- F1：赛道曲线、DRS 直线、圈速折线。

### 8.4 品牌母题：PULSE LINE

PULSE LINE 不是装饰性波浪，而是一条有信息职责的连续轨迹：

| 状态 | 形态 | 用途 |
|---|---|---|
| Ambient | 1px 暗红连续线 | 页面分区、背景方向感 |
| Upcoming | 短实线 + 时间刻度 | 距离封盘的时间关系 |
| Live | 荧光点沿红线推进 | 真实进行中的 Session |
| Locked | 线条在切口处收束 | 封盘反馈 |
| Settled | 线条闭合为结果印章 | 结算完成与历史记录 |

它在不同运动中改变几何语法，但不改变品牌身份：足球呈圆弧与传球折线，篮球呈半场弧线，F1 呈赛道和计时扇区。禁止使用无意义的心电图折线、随机粒子和持续发光。

### 8.5 构图纪律

- 页面默认左对齐，标题不机械居中；
- 每个首屏只允许一个超大视觉焦点；
- 使用 `7/5`、`8/4`、`5/7` 等不对称分栏，避免连续三等分卡片；
- 信息层级优先通过字号、位置和留白表达，边框和阴影只做最后一级区分；
- 卡片不套卡片；同一屏圆角容器不超过两层；
- 阴影只用于悬浮 Prediction Slip 和移动端底部抽屉，普通赛事列表依靠分隔线组织；
- 赛事详情、房间和后台至少保留 60% 中性阅读区域，不让红色压过数据。

## 9. 动效系统

动效目标是制造速度与反馈，不是展示技术。

### 9.1 页面进入

```text
PULSE LINE 从左侧完成一次描线       260ms
标题沿 11° 切口显现                 420ms
主 CTA 与实时状态依次进入           60ms stagger
赛事条在首屏稳定后进入，不自动抢焦点
```

### 9.2 Sport Switch

用户从足球切到 F1 时：

- 红色轨迹线横向扫过；
- 内容交叉淡入淡出 180–240ms；
- 不整页白屏；
- 保留日期和房间上下文。

### 9.3 比赛状态

- 即将开始：时间轻微闪动一次，不循环；
- LIVE：小型脉冲动画，2 秒一次；
- 封盘：选择区从彩色收敛为灰色；
- 结算完成：积分数字滚动到新值；
- 失败：局部抖动不超过 4px，并配合明确文本。

### 9.4 性能规则

- 优先 `transform` 和 `opacity`；
- 不为列表每一行添加持续动画；
- 首屏视频必须有静态 Poster；
- `prefers-reduced-motion` 下取消位移、Marquee 和数字滚动；
- 低端移动设备不加载复杂粒子背景。

## 11. 首页详细设计

### 11.1 首屏 Hero

首屏不是传统“左文案、右图片”的 SaaS 模板，而是一张会随赛事状态变化的数字封面。

桌面结构：

```text
┌──────────────────────────────────────────────────────────┐
│ PULSE                 赛事 房间 战绩 排行         登录   │
│ 01 / TODAY                                               │
│ CALL                                                     │
│ THE                     ┌──── 当日主赛事裁切画面 ─────┐  │
│ MOMENT.                 │ PULSE LINE 穿过画面与标题   │  │
│                         └─────────────────────────────┘  │
│ 每一刻，都有判断。                         03 SPORTS     │
│ 足球、篮球、F1。                          12 EVENTS      │
│ [浏览今日赛事 →]                         LIVE 仅有数据时 │
└──────────────────────────────────────────────────────────┘
```

视觉：

- 碳黑背景；
- `CALL` 使用暖白实心，`THE` 缩小成为节奏停顿，`MOMENT.` 使用赛车红实心，不使用渐变字；
- 当日主赛事画面以 11° 斜切裁边压入标题区，故意打破 12 列网格；
- 右侧不是固定赛车照片，也不做三张轮播 Banner；每天根据最近一场重点赛事切换一张主视觉；
- PULSE LINE 从 `P` Logo 内部出发，穿过标题、主视觉，再落入下方 Live Rail；
- 未登录用户只保留一个红色主 CTA“浏览今日赛事”，创建房间降为文字入口；
- `LIVE` 只在真实存在进行中赛事时出现，否则显示下一场倒计时，绝不伪造实时感；
- 首屏下沿露出下一章节约 64px，提示页面可以继续滚动。

手机端不是桌面缩小版：标题占上半屏，主赛事图片裁成横向窄条插入 `THE` 与 `MOMENT.` 之间；赛事数量和倒计时放在图片下方，主 CTA 固定在首屏内容末端，不覆盖底部导航。

### 11.2 Live Rail

首屏下方使用横向赛事条：

```text
LIVE  NBA · 湖人 101–98 勇士  ·  Q4 05:32
NEXT  F1 · 英国大奖赛排位赛  ·  周六 22:00
NEXT  英超 · 阿森纳 vs 曼城   ·  周日 23:30
```

不是无意义 Marquee，点击后进入对应赛事详情。

### 11.3 三项运动章节

使用一条“赛道式目录”，而不是三张相同圆角卡。默认突出最近有赛事的运动，另两项作为窄幅章节入口：

```text
FOOTBALL    6 / 12 columns
BASKETBALL  3 / 12 columns
FORMULA 1   3 / 12 columns
```

悬停时显示：

- 今日赛事数；
- 下一场时间；
- 房间内热门预测；
- 进入运动入口。

鼠标移动到运动入口时，只让对应的轨迹线和数字发生变化，不做整卡上浮、发光边框或 3D 倾斜。手机端改为三个连续的全宽章节，通过滚动自然浏览，不隐藏赛事入口。

### 11.4 产品机制章节

用四个连续编号而不是普通功能卡：

```text
01 选择赛事
02 提交判断
03 自动封盘与结算
04 和朋友长期排名
```

### 11.5 合规表达

页面底部保留：

> 仅使用虚拟积分，不支持充值、提现或兑换。18 岁以上用户可使用。

不需要在每个 Hero 重复大段说明，但注册、预测提交和页脚必须明确。

```text
BELGIAN GRAND PRIX                         19–21 JUL
────────────────────────────────────────────────────
Q   排位赛            SAT 22:00          即将开放
R   正赛              SUN 21:00          12 个市场
──────────────────────────── PULSE LINE ────────────
```

### 12.5 F1 市场与结算规范（2026-07-17 拍板）

**数据模式**：F1 不依赖实时数据供应商，采用**管理员手动录入结果 + 自动结算**。一个大奖赛周末最多 4 个可预测 Session，结果各录入一次即可结算。后续可选接入免费结构化数据（如 jolpica / Ergast 系）做自动预填，管理员确认后结算。

**Session 结构**（普通周末 2 个，冲刺周末 4 个；2026 赛季 6 站冲刺）：

| Session | 可预测内容 | 封盘时间 |
|---|---|---|
| 排位赛 Qualifying | 杆位 / 前三 | Q1 开始 |
| 冲刺排位 Sprint Qualifying | 杆位 / 前三 | SQ1 开始 |
| 冲刺赛 Sprint | 冠军 / 前三 | 起跑灯灭 |
| 正赛 Grand Prix | 冠军 / 前三 | 起跑灯灭 |

**v1 市场**：

1. **Session 冠军**：杆位（排位类）或冠军（比赛类），单选。
2. **领奖台·基础**：某车手进前三，是/否，低倍率。
3. **领奖台·精确顺序**：1-2-3 名全对才中，高倍率，仅高级房间开放，复用 Correct Score 的高倍率票据与结算框架。
4. **车手对决 H2H**：任选任意两位车手预测完赛先后，**不设预设组合，一切配对皆可成立**。倍率由系统按两位车手的赛季积分/近期成绩差距公式自动生成，管理员可覆盖个别组合——既不必为 231 种配对手工定价，也避免「强弱悬殊对决双边同倍率」变成无风险刷分。解决强队独走时冠军市场缺少悬念的问题。

以上四类 Session 结构属于已确认范围，后续不得为了缩减工程量删除排位赛、冲刺排位、冲刺赛或正赛的“杆位/冠军 + 前三”入口。第一阶段可以分批开放市场，但 UI 与通用事件模型必须预留完整结构。

**v2 及以后**：赛季总冠军 / 车队总冠军长线盘。**不做**：最快圈、安全车、退赛数等 prop 盘（与 §4.3 合规语言方向冲突）。

**结算规则**：

- 以 Session 结束后的**官方分类成绩（含当场判罚）**为准；数日/数周后的追溯处罚**不重开已结算票**，写入房间规则页。
- 排位类按排位成绩结算，不受正赛发车罚退影响。
- H2H 的 DNF 规则：一方完赛则完赛方胜；双方退赛则完成圈数多者胜；同圈退赛判平并退还积分。
- 车手 DNS（赛前退出）：涉及该车手的票退还积分。

**倍率来源**：v1 由房主/管理员按模板预设倍率（热门 2–4x、中游 8–15x、长尾 30x+，精确前三固定高倍）；H2H 例外，按上述公式自动定价。彩池制（投入合池按比例分）作为远期备选，属机制级改动，不在本次范围。

## 13. 赛事详情与预测 Slip

### 13.1 桌面布局

```text
┌────────────────────赛事信息 8列───────────────────┬──Slip 4列──┐
│ 状态、比分、阵容/车手、市场、时间线                │ 当前选择    │
│                                                    │ 投入积分    │
│                                                    │ 预计返还    │
│                                                    │ 确认提交    │
└────────────────────────────────────────────────────┴────────────┘
```

Slip 在桌面 sticky，手机端成为底部抽屉。

### 13.2 预测交互

- 先选择 outcome，再输入积分；
- 选择后立刻在卡片显示赔率版本和最后更新时间；
- “预计返还”必须同步显示；
- 提交按钮文案为“确认最新倍率并提交”；
- 已封盘时保留选择结果，但按钮变为不可提交并解释原因；
- 多市场时每个市场独立分组，不把所有结果放在一个大网格中。

### 13.3 Prediction Slip 视觉结构

Slip 是操作工具，不做成霓虹悬浮控制台：

```text
YOUR CALL / 本次判断                         01
──────────────────────────────────────────────
比利时大奖赛 · 排位赛
杆位获得者

04  LANDO NORRIS                         3.20×
──────────────────────────────────────────────
投入积分                                  2,000
预计返还                                  6,400

[确认最新倍率并提交 →]
数据更新于 18:42 · 封盘倒计时 01:18:32
```

- 顶部红色切角只标识当前选择数量，不给整个容器铺红底；
- 车号、时间、倍率和积分使用等宽数字，赛事名称与操作文案使用正文字体；
- 主按钮提交前为赛车红，提交中由 PULSE LINE 横向完成一次进度反馈；
- 成功后 Slip 不弹出彩带，而是收束成一张带结算状态的“判断凭证”；
- 移动端抽屉默认只露出“已选 1 项 / 预计返还”，上拉后展示完整内容；
- 多个市场使用纵向分组与分隔线，不使用四列等宽按钮墙。

## 20. 后端与 UI 的依赖边界

视觉原型可以先做，但正式 F1 UI 依赖通用事件模型。

当前主客队模型应逐步升级为：

```text
sports
competitions
events
participants
event_participants
markets
market_outcomes
tickets
ticket_legs
settlements
```

UI 只依赖统一合同：

```ts
type EventCardModel = {
  id: string;
  sport: "FOOTBALL" | "BASKETBALL" | "FORMULA_1";
  competition: string;
  startsAt: string;
  state: "UPCOMING" | "LIVE" | "FINISHED";
  participants: ParticipantView[];
  score?: ScoreView;
  featuredMarkets: MarketView[];

```

足球和篮球可有两个 participants；F1 可以有 22 位车手（2026 赛季）。

## 21. 实施路线

### Phase 0：冻结当前功能基线，1–2 天

- 完成当前工作区尚未提交的功能（含 RBAC 审计修复等未提交变更）；
- 全量测试并部署；
- 创建 `feature/pulse-brand-system`；
- 保留现有足球功能作为回归基线。

**注意：足球版已上线且有真实用户。** 改版全程在 feature 分支进行，不阻塞线上修复；品牌切换（名称、PWA 图标、Metadata）属于对存量用户可见的变更，上线时需要一次性发布并配合房间内公告，避免用户以为换了产品。

### Phase 1：品牌原型，3–5 天

- PULSE Logo 三个草案，其中至少一个完成 24px 图标、桌面字标和动态状态验证；
- 色彩和字体样板；
- PULSE LINE 在足球、篮球、F1 三种场景中的同源变体；
- 首页桌面/移动稿；
- Header、Sport Switcher；
- 三类赛事卡静态原型；
- 房间首页静态原型。

验收后再进入工程化。

### Phase 2：Design System 工程化，4–6 天

- 新 Token；
- 通用 Logo 和图标；
- 按钮、标签、卡片、数据状态；
- 新 App Shell；
- 统一响应式和动效；
- Storybook 或专用 `/design-system` 开发页。

### Phase 3：品牌替换与足球迁移，4–6 天

- Metadata、PWA、Logo；
- 首页；
- 登录注册；
- 足球赛事卡迁移；
- 房间、战绩、排行榜视觉迁移；
- 保证现有足球功能无回归。

### Phase 4：通用赛事模型，10–16 天

- 新数据库模型；
- 旧足球数据兼容层；
- 通用 API；
- 通用市场和结算接口；
- 数据迁移与回滚脚本。

估期依据：HOME/DRAW/AWAY 三向结果模型贯穿 `packages/domain`（ticket-submission、competition）、`packages/db`（settlement、supplier snapshot adapter）、`packages/supplier`、`packages/contracts` 全链路；Correct Score 功能新增的比分市场与 `legs_selection_check` 约束也需纳入通用模型；结算引擎 + 赔率版本快照 + 兼容层的改造量按原估 2 倍计。

### Phase 5：F1，5–8 天（提前于篮球）

- 赛历、分站、Session（排位/冲刺排位/冲刺赛/正赛，见 §12.5）；
- 车手、车队（2026 赛季 11 队 22 人）；
- 管理员结果录入界面与自动结算；
- Session 冠军、领奖台（基础 + 精确顺序）、车手对决四类市场；
- F1 赛事详情卡与房间 F1 战绩。

提前理由：手动录入模式无数据源风险；当前正值 F1 赛季中段，上线即有比赛可玩。

### Phase 6：篮球，5–8 天（前置数据源验证）

- **先做 1–2 天数据源 spike**：验证候选免费源（如 balldontlie 类）的额度、延迟、中文球队名可得性，spike 结论决定本阶段是否启动；
- 当前赛季数据源；
- 中文球队名；
- 胜负、让分、总分；
- 篮球赛事卡和结算；
- 房间篮球战绩。

延后理由：NBA 处于休赛期（新赛季 10 月下旬开始），现在完成也无比赛可玩，正好利用窗口期验证数据源。

预计稳定版本需要 5–7 周；篮球一项取决于数据供应商 spike 结论，F1 与足球不再依赖外部实时数据能力。

## 22. 第一版验收标准

### 品牌

- 页面不再把 football 作为平台名称；
- Logo 在 24px 和 160px 都清晰；
- Logo 不依赖足球、篮球或赛车图形；
- 不使用 Ferrari 跃马、盾牌或 SF 识别；
- PWA、Metadata、登录页和邮件/分享标题统一。

### UI

- 首页桌面和移动端均无横向溢出；
- 三项运动可在 2 次点击内进入；
- 足球、篮球、F1 卡片结构明显不同但属于同一品牌；
- 所有主要操作达到 44×44px 以上；
- 小文字不使用白字配亮红底；
- 键盘焦点明确；
- Reduced Motion 下没有持续位移动画；
- 国内网络不依赖外部字体和运行时图片 CDN。
- 页面关闭 Logo 后仍可通过 PULSE LINE、11° 切口和构图方式识别品牌；
- 不出现紫蓝渐变、玻璃拟态、发光卡片墙、无意义数据仪表盘或三等分功能卡；
- 同一屏最多一个大红色焦点，荧光黄绿只表达真实实时状态；
- 首页、赛事中心、F1 周末卡、Prediction Slip 和房间页必须形成五种不同构图，而不是同一张卡片换内容；
- 视觉评审必须包含 1440px、1024px、390px 三个断点的整页截图，不能只评孤立组件。

### 产品

- 用户始终能确认运动、赛事、开赛时间和数据更新时间；
- 已封盘和已完赛不能提交；
- F1 不出现主队/客队文案；
- 篮球不出现平局选项；
- 历史记录可按运动筛选；
- 房间余额和账本仍保持统一。

## 23. 明确不做的事情

- 不一次性删除现有足球模型；
- 不在数据源验证前承诺篮球/F1 实时能力；
- 不复制 Lando Norris 官网布局或媒体素材；
- 不使用 Ferrari 跃马和黄色盾牌；
- 不把每个页面都做成全屏红色海报；
- 不让三项运动拥有三套互不兼容的 Design System；
- 不把虚拟积分产品写成现金博彩语言；
- 不为了动效牺牲首屏速度和移动端体验。

## 25. 最终设计结论

项目下一版不应该只是“把篮球和 F1 图标加进足球网站”，而应该建立一个真正的多运动品牌。

推荐方向是：

> **PULSE：赛车红主导、碳黑承载、暖白阅读、荧光黄绿点亮实时数据。**

它继承 Lando Norris 官网的高冲击运动员视觉，提取红色跃马所代表的速度、力量与俱乐部感，但形成自己的 Logo、颜色比例和产品语言。首页大胆、业务页克制；品牌统一、运动卡差异化；先做视觉原型，再做通用赛事模型。

这会让产品从一个足球预测工具，升级成具有长期扩展能力和明确品牌资产的体育社交平台。
