# 联赛分类与完赛胜者展示设计

## 目标

让比赛页以联赛为第一层分类，用户可以用联赛标签快速筛选；已结束比赛显示最终比分，并明确指出获胜球队或平局。

## 方案比较

1. **联赛标签 + 联赛优先分组（采用）**：顶部提供“全部/各联赛”标签，内容按“联赛 → 日期 → 比赛”展示。信息层级最明确，移动端也容易操作。
2. **保留下拉框，仅调整分组顺序**：改动较小，但联赛入口不够醒目，用户仍需展开下拉框。
3. **每个联赛独立页面**：URL 和分享能力更强，但会引入路由、空状态和导航维护，当前需求不需要。

## 数据流

1. `supplier.fixtures` 已保存 `result_confirmed`、`home_score`、`away_score`、`result_version`。
2. 数据库仓储读取比赛时一并返回赛果字段。
3. 比赛 API 继续使用现有 `MatchView`，把已确认的赛果传给前端。
4. 前端规范化数据时只接受有限数值比分；胜负由比分现场推导，不存重复的 winner 字段。
5. 比赛卡片在 `FINISHED` 状态下显示比分和“球队名胜/平局”；赛果缺失或未确认时显示“赛果待确认”。

## 界面结构

- 筛选区：状态标签、联赛标签、日期选择、刷新按钮。
- 列表结构：联赛标题及场次数 → 比赛日期 → 卡片网格。
- 完赛卡片：中央 `2 : 1` 最终比分，下面显示“英格兰胜”；平局显示“平局”。
- 未完赛卡片保持现有 `VS`、开球时间、积分倍率和预测入口。

## 错误与降级

- `FINISHED` 但赛果未确认：不猜测胜者，显示“赛果待确认”。
- 非数字、负数或不完整比分：前端忽略该赛果并按待确认处理。
- 联赛名称缺失：沿用“未标注联赛”。

## 测试

- 数据库仓储测试：验证赛果列映射到比赛快照。
- 前端规范化测试：验证有效赛果、未确认赛果和非法比分。
- 分组测试：验证联赛优先、日期次级及开球顺序。
- 卡片渲染测试：验证主队胜、客队胜、平局、待确认四种显示。
